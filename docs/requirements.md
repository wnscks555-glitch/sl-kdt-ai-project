# 요구사항 초안

기준: [v6](../../outputs/제조기술개발_프로젝트_주제와핵심기능_v6.md). 아래 예상 결과는 구현 전 정한 **가상 규칙**이며 아직 실행 결과가 아닙니다.

## 목표와 제외 범위

- 제조기술개발 단일 직무를 위한 가상 조립·검사 진행 관리.
- 한 제품의 예비 조립·본조립을 각 한 번만 처리한다.
- 점등·누설은 실측값이 아닌 합성 PASS/FAIL 입력이다.
- 최종 상태명은 **「선택한 두 검사까지의 모의 흐름 완료」**다. 출하·양품·SL 기준 적합을 뜻하지 않는다.
- 외관·광도 검사, 다회차 재조립, 기존 검사 결과 정정, 제품 내 GPT 기능과 설비 연동은 기본 범위에서 제외한다.

## 필수 요구사항

| ID | 요구사항 | 확인할 결과 |
| --- | --- | --- |
| R1 | 제품 등록과 예비 조립→본조립 순서 | 선행 단계 없이 다음 단계 입력 시 거절 이유 표시 |
| R2 | 두 검사 최초 결과와 미실시 구분 | 제품·검사·시도·사건 ID와 PASS/FAIL 또는 검사 대기 조회 |
| R3 | FAIL 보류 | FAIL 뒤 제품 완료 불가, 해당 사건과 보류 이유 표시 |
| R4 | 재검사 요청 | 같은 제품·검사 종류의 미해결 FAIL 시도 지정. 요청만으로 보류 해제 불가 |
| R5 | 새 검사 시도와 요청 연결 | 재검사 결과에 새 시도 ID와 유효한 `재검사 요청 사건 ID` 필수 |
| R6 | 보류 해제와 완료 | 유효한 새 PASS만 해당 보류 해소. 두 검사 PASS·미해결 FAIL 없음일 때만 모의 흐름 완료 |
| R7 | 이력 불변·잘못된 입력 | 이전 FAIL·요청·새 결과 보존. 같은 시도의 두 번째 결과나 유효하지 않은 요청은 거절 이유 기록 |
| R8 | 저장·재실행·표시 | 재조회 후 상태·이력 유지, 고정 입력 재실행의 논리 결과 동일, 현재 상태의 이유 표시 |

## 구현 전에 고정할 시나리오

| ID | 합성 입력 | 예상 결과 |
| --- | --- | --- |
| S1 | 예비·본조립 완료, 점등 PASS, 누설 PASS | 선택한 두 검사까지의 모의 흐름 완료 |
| S2 | 예비 조립 없이 본조립 | 거절, 빠진 선행 단계 표시 |
| S3 | 조립 완료, 점등 PASS, 누설 미실시 | 검사 대기, 완료 불가 |
| S4 | 조립 완료, 점등 PASS, 누설 L1 FAIL | 누설 보류, L1 보존 |
| S5 | S4 뒤 검토 메모·재검사 요청만 입력 | 보류 유지 |
| S6 | S4 뒤 L1 지정 요청 R1, 새 L2 PASS가 R1 참조 | L1·R1·L2 보존, 누설 보류 해소. 점등도 PASS면 완료 |
| S7 | S4 뒤 요청 없는 L2 PASS | 거절, 보류 유지 |
| S8 | S4 뒤 L1 시도 ID에 PASS 덧입력 | 거절, 원래 FAIL 유지 |
| S9 | S4 뒤 R1에 연결된 L2 FAIL | 보류 유지, 다시 시도하려면 새 요청 필요 |

구현 전 결정: 사건·시도 ID의 유일성 범위, 이벤트 순서 기록, 저장 방식 하나(JSON/CSV 또는 SQLite), 첫 사용 방법(명령줄 권장). 예상 결과를 코드 출력에 맞춰 바꾸지 않는다.
